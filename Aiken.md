# PRD: Реестр нарушений дедлайнов и штрафов

## 1. Контекст и проблема

Команда работает с несколькими аутсорсинговыми компаниями по проверке качества контента. Разные подрядчики выполняют разные типы задач (модерация UGC, разметка данных, проверка карточек товара и т.д.) по разным договорам, каждый со своими условиями по срокам и штрафам за их нарушение.

Сейчас нет единого места, где фиксируются:
- факты срыва дедлайнов подрядчиками;
- расчёт штрафа по условиям конкретного договора;
- статус штрафа (начислен / выставлен счёт / оплачен);
- ссылка на подтверждающий счёт во внешней системе.

## 2. Цель продукта

Дать команде единый общий реестр, в котором:
1. хранятся правила расчёта штрафов по каждому подрядчику и типу задачи;
2. фиксируются сами нарушения дедлайнов с автоматическим расчётом суммы штрафа;
3. видна сводная картина — сколько начислено, оплачено и должно быть оплачено по каждому подрядчику.

## 3. Пользователи

Несколько человек в команде работают с приложением одновременно, данные — общие (не приватные для каждого пользователя). Все участники видят одни и те же правила, нарушения и сводку в реальном времени.

## 4. Границы продукта (что это НЕ делает)

- Приложение **не проводит платежи** и не является платёжной или бухгалтерской системой.
- «Ссылка на счёт» — это просто произвольная ссылка на уже существующий счёт/документ во внешней системе (бухгалтерия, облако и т.п.), а не автоматическая генерация или отправка счетов.
- Нет интеграции с внешними бухгалтерскими/CRM-системами — только ручной ввод ссылки.

## 5. Функциональные требования

### 5.1 Вкладка «Правила»
Позволяет задать формулу штрафа для пары «подрядчик + тип задачи/договора», поскольку у разных договоров разные условия.

Поля правила:
- Подрядчик (текст)
- Тип задачи / договор (текст)
- Тип штрафа (один из трёх):
  - **Фиксированная сумма за день просрочки** — штраф = сумма × количество дней просрочки
  - **Процент от суммы контракта за день** — штраф = сумма контракта × (процент / 100) × количество дней просрочки
  - **Фиксированная сумма за факт нарушения** — штраф = фиксированная сумма, не зависит от количества дней
- Значение штрафа (число; для типа «процент» — величина в %)
- Сумма контракта/задачи (только для типа «процент от суммы»)
- Валюта (₸, ₽, $, €)
- Примечание (необязательно, например ссылка на пункт договора)

Действия: добавить правило, удалить правило (удаление правила не удаляет уже зафиксированные по нему нарушения).

### 5.2 Вкладка «Нарушения»
Форма фиксации нарушения:
- Выбор правила из списка (подрядчик — тип задачи)
- Задача/описание (текст)
- Дедлайн (дата)
- Фактическая дата сдачи (дата)
- Ссылка на счёт (необязательно, URL)
- Комментарий (необязательно)

Логика:
- Просрочка в днях = фактическая дата − дедлайн (не может быть отрицательной; при отсутствии просрочки штраф = 0).
- Сумма штрафа считается автоматически по правилу выбранного подрядчика и отображается как предпросмотр до сохранения.
- После сохранения запись появляется в журнале нарушений (сортировка по дедлайну, последние сверху).

Журнал нарушений показывает по каждой записи: подрядчика, тип задачи, задачу, дедлайн → факт, количество дней, сумму штрафа, ссылку на счёт (если есть), статус.

Статус нарушения (редактируется прямо в журнале):
- Новое
- Счёт выставлен
- Оплачено

Действия: удалить запись о нарушении.

Внизу журнала — итоговая сумма начисленных штрафов по всем записям, сгруппированная по валюте.

### 5.3 Вкладка «Сводка»
Таблица по подрядчикам (группировка по подрядчику + валюте):
- Количество нарушений
- Сумма начисленных штрафов
- Сумма оплаченных штрафов
- Сумма к оплате (начислено − оплачено)

## 6. Модель данных

**rules** (правила):
`id, company, contractName, penaltyType (fixed_day | percent_day | fixed_violation), penaltyValue, contractAmount (только для percent_day), currency, note, createdAt`

**violations** (нарушения):
`id, ruleId, company, contractName, penaltyType, task, deadline, actual, daysLate, penaltyAmount, currency, invoiceUrl, comment, status (new | invoiced | paid), createdAt`

Данные общие для всех участников команды и синхронизируются в реальном времени между всеми, кто открыл приложение.

## 7. Принятые решения (из уточняющих вопросов)

| Вопрос | Решение |
|---|---|
| Как считать штрафы? | Разные правила для разных типов задач/договоров (гибкая настройка на уровне пары «подрядчик + договор») |
| Что значит «ссылка на счета»? | Ручная ссылка на уже существующий счёт во внешней системе, без автогенерации |
| Сколько пользователей? | Несколько человек в команде, данные общие |

## 8. Нереализованные вопросы / возможные развития

- Экспорт реестра (например, в Excel/CSV) для отчётности.
- Уведомления/напоминания об истекающих дедлайнах.
- Права доступа (например, только часть команды может удалять записи).
- История изменений статуса штрафа (аудит-лог).
- Множественная валюта в рамках одного подрядчика уже поддерживается на уровне сводки (группировка по подрядчик+валюта), но нет конвертации в единую валюту.
